指示書の「推測でAPIを使わない（実コード確認）」に従い、迷ったところは
**統合版／教育版の本物の定義ファイルを読んで**決めた。読んだ場所は

```
C:\Program Files\WindowsApps\Microsoft.MinecraftEducationEdition_1.26.3200.0_x64__8wekyb3d8bbwe\data\
  behavior_packs\vanilla\entities\*.json      … AI(behavior.*)の正しい書き方
  resource_packs\vanilla\models\entity\*.json … モデルの書き方
  resource_packs\vanilla\sounds.json          … 実在する音ID
  behavior_packs\vanilla\items\*.json         … 食料アイテムの本当のID
```

（統合版の exe は読めないが、教育版は読める。中身は同世代なのでこれで裏が取れる）

## 1. なぜ Java版MODではなく統合版アドオンなのか

指示書の最重要ルール1「既存リポジトリを必ず調査する（Mod Loader / Minecraft
バージョン特定）」に従って統合アプリ配下を調べた結果:

| 既存物 | 形式 |
|---|---|
| ドローンMOD | 統合版アドオン（BP+RP、`@minecraft/server` 2.0.0） |
| 重機MOD | 統合版アドオン |
| 水害MOD | 統合版アドオン |
| 治水ゾンビ | 統合版ビヘイビアパック |
| 鉄道MOD | 統合版アドオン（Javaデモは別に1件だけ） |

**この端末の資産はすべて統合版アドオン**で、熊が徘徊する舞台になる
PLATEAUの都市ワールドも統合版（`.mcworld`）。同じ土俵に載せた。

`@minecraft/server` の版と `min_engine_version` は、実際に動いている
ドローンMODと同じ **2.0.0 / 1.21.80** に合わせた（動作実績のある組み合わせ）。

## 2. いちばん大きな判断: 「歩かせ方」

**統合版のスクリプトAPIには「この座標へ歩け」という命令が無い。**
経路探索を持っているのはバニラのAI（`minecraft:behavior.*`）だけ。
取れる道は3つあった。

| 方法 | 結果 |
|---|---|
| テレポートで動かす | 地形を無視した滑りになる。「徘徊」に見えない。却下 |
| `applyKnockback` で押す | 壁にぶつかる。段差を越えられない。却下 |
| **行き先に狙える相手を置いて追わせる** | 経路探索・段差・階段・ドアの開閉が全部タダで付く。採用 |

採用した形:

```
bear:lure（見えない目印）を行き先に置く
  ↓
熊の nearest_attackable_target が「bear_lure 家系」を狙う
  ↓
move_towards_target で歩く（within_radius: 1 なので目の前まで行く）
```

スクリプトの仕事は**「どこへ行くか」を決めて目印を動かすだけ**になり、
歩き方はバニラ品質になる。ドアを開けて入るのも
`annotation.open_door` + `behavior.open_door` + `navigation.walk.can_open_doors`
（村人と同じ組み合わせ）に任せている。

### 状態はAIの型ごと差し替える

`component_groups` を4つ用意し、スクリプトが `triggerEvent` で切り替える。

| 型 | 中身 | 使うとき |
|---|---|---|
| `bear:mode_roam` | 目印を狙う + 目印へ歩く（速度1.0） | 徘徊・家へ・チェストへ・復帰 |
| `bear:mode_flee` | 目印を狙う + 目印へ歩く（速度1.7） | 逃走 |
| `bear:mode_hunt` | プレイヤーを狙う + 殴る | 攻撃 |
| `bear:mode_still` | 何も狙わない | 略奪中・ドアを叩いている間 |

`hurt_by_target`（殴られたら反撃）は**あえて入れていない**。
入れるとバニラが勝手に反撃を始めて、指示書の優先順位
（逃走 > 攻撃）をスクリプトが握れなくなる。撃たれたときの判断は
`entityHurt` を受けて `bear.js` が決める。

## 3. 「1〜3撃で倒す」の作り

エンティティ定義の `minecraft:attack.damage` は**スクリプトから変えられない**。
そこで

- `bear.json` の `minecraft:attack.damage` は **1**（＝「殴った」判定を出すためだけ）
- `entityHitEntity` を受けて、スクリプトが残りを上乗せする

上乗せ量は固定値ではなく **相手の最大体力から逆算**する:

```
一撃 = ceil(相手の最大体力 ÷ その個体の撃数) - 1   （-1 は素の1のぶん）
撃数 = 1 + 2 × (1 - 攻撃性)                        → 攻撃性1.0で1撃、0.0で3撃
```

体力上限を変えるアドオンと併用しても「1〜3撃」が保たれる。
防具で撃数が増えないように、既定では `cause: "override"`（防具を無視）で
与えている（`ATTACK_IGNORE_ARMOR = false` にすると防具が効く）。

`ATTACK_COOLDOWN`（20tick）で二重適用を防いでいる。

## 4. ブロック走査を「重くしない」作り

家探しは半径24×高さ8で**約2万ブロック**。1tickで読めば確実に落ちる。
指示書の「毎tick全探索は禁止 / 探索間隔10〜20tick」を、次の形で守った。

- 走査はすべて `scan.js` を通す。**1tickの読み取り数に上限（既定700）**をかけ、
  複数の走査があれば予算を分け合う（頭数が増えても総量は増えない）
- **近いところから読み**、必要な数（家なら6件）見つかったら途中でやめる
- 熊の面倒は `TICK_INTERVAL`（10tick）ごと。1tickにまとめて全頭を見ない
- 地形（森・水・畑・道路）は `getTopmostBlock` を4ブロックおきに読む（列を1回読むだけ）

机上試験で **10頭同時に家探し**をさせたときの実測が **最大717読み取り/tick**
（上限700＋足元の高さ測りぶん）。頭数を増やしても、この値は上がらない設計。

熊の数自体にも上限（`MAX_BEARS` = 24頭）を置き、超えたら
**プレイヤーからいちばん遠い熊**から消す（目の前で消えると不自然なので）。

## 5. 「食料だけ」の見分け方

統合版のスクリプトAPIは、版によって `ItemStack` から `minecraft:food` の部品が
読めない（この端末の机上試験では読めなかった）。**推測せず二段構え**にした。

1. `config.js` の `FOOD_ITEMS` 一覧で判定（これが本筋）
2. 起動時に一度だけ `minecraft:food` 部品を試し、**使えたときだけ**併用する
   （他アドオンの食料も拾えるようになる）

一覧は教育版の `behavior_packs/vanilla/items/*.json` から**実物のIDを抜いて**作った。
統合版は古い内部IDを返すことがある（`cod`→`fish`、`mutton`→`muttonRaw`、
`melon_slice`→`melon`）ので、新旧どちらも入れてある。

**チェストを壊すときは、残った中身を床にこぼしてから壊す。**
壊すついでに他人の道具を消すのは「食料のみ略奪」に反するため。

## 6. 見た目（自作した理由）

バニラの `geometry.polarbear` を借りれば楽だが、

- バニラの内部名に依存する（名前が変わると壊れる）
- 白熊の体型のまま
- 配布時に素材の権利がややこしくなる

ので、**モデル・テクスチャ・アニメーションをすべて自作**した。

- `geometry.bear` … 肩高1.4m / 全長1.9m のヒグマ体型。ヒグマの見分けどころである
  **肩のこぶ**を背中の前寄りに付けた。骨の名前は quadruped の慣習
  （`leg0`/`leg1`=後脚、`leg2`/`leg3`=前脚）に合わせ、対角の脚が同時に出る
- テクスチャは `tools/make_textures.py` が生成（種を固定してあるので毎回同じ絵）。
  UVの位置はモデルと厳密に対応し、**ずれたら `check_uv.py` が落ちる**
- 動きは3つ。`walk`（歩いた距離で脚を振る＝止まれば止まる）、
  `look`（狙う相手を見る）、`sniff`（狙う相手がいないとき鼻先を上下＝熊らしさ）
- 音は統合版に実在する `mob.polarbear.*` を、ヒグマらしく音程を下げて鳴らす
  （音ファイルは同梱しない）

誘導体 `bear:lure` は**箱を1つも持たないモデル**にして、画面に出ないようにした。

## 7. 定義JSONにコメントを書かない理由

`"//": "説明"` という書き方は世間のアドオンでよく使われるが、

- バニラの定義ファイルは使っていない
- この端末の既存MOD（ドローン・重機・水害・鉄道）も使っていない
- **無視される保証を実物で確認できなかった**

統合版は定義の間違いを無言で流す（＝エンティティが消える・見た目が出ない）ため、
確認できない書き方は避けた。説明はこのメモに置き、
`validate.py` が「定義JSONに `//` キーが残っていないか」を見張っている。

## 8. 検査の考え方

**実機で遊べないので、遊ばずに分かることは全部自動で見る。**
水害MODで「静的検査は全部通ったのに実機のTier1が動いていなかった」という
失敗があるので、次の3段構えにした。

1. **静的検査**（Python）… 定義の参照先が実在するか、二重に書いた数値がずれていないか
2. **机上試験**（Node）… `@minecraft/server` を偽物に差し替えて、
   **本物のスクリプトをそのまま**動かす。写しは作らない（写し間違いで
   「試験は通るが実機は動かない」になるため）
3. **逆テスト** … 起きてはいけないことが起きないか
   （確率0なら壊さない、しきい値未満では逃げない、クリエイティブは襲わない…）

さらに、**検査そのものが空回りしていないか**も一度確かめた。
体力の数値・状態名・UV・モデル参照をわざと壊し、4つの検査が全部落ちること、
戻すと全部通ることを確認済み。

### 机上試験で見つかって直したもの

| 症状 | 真因 |
|---|---|
| 家に入れず「中が分からない」になる | 走査が**ドアの上半分**を先に見つけていた。上半分は足元が空気なので、家の中の判定が全部外れる。基準を必ず下半分に揃えた（`lowerDoor`） |
| ドアを必ず壊してしまう | 開ける／壊すのくじを**毎周期**引いていた。ドアに着いたときに一度だけ引くようにした |
| 熊を消したあとに見えない目印が残る | ブロック走査の返事は数tick遅れて届く。その間に熊が消えていると、**死んだ熊のために目印を作っていた**。`rec.gone` で止めた |
| （試験側）家の中を探しているのに屋根の上を探す | 偽物の物理が熊を「いちばん上のブロック」に立たせていた。床に着地させるよう直した |

## 9. 実機で確かめること

机上試験には経路探索も当たり判定も無い。README の第6節のチェックリストを
実機で1つずつ見る。特に見てほしいのは

1. **目印方式が本当に効くか**（`move_towards_target` の `within_radius: 1` で
   目の前まで来るか）。効いていなければ熊は徘徊のまま動かない
2. **ドアを開けて入るか**（`behavior.open_door` が経路に乗るか）
3. **1〜3撃**が防具ありでも保たれるか（`cause: "override"` が効いているか）

1 が駄目だった場合の逃げ道は `config.js` の `LEG_DISTANCE` を縮める（近くに置く）。
それでも駄目なら、`bear.json` の `mode_roam` の `within_radius` を 1 → 0 にする。
