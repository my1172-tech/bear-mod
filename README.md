# 熊AI MOD（Minecraft 統合版アドオン）

町へ下りてきて家をあさる熊のシミュレーション。敵モブではなく**野生動物**として作ってある。

- 森・山・市街地の外周に湧く
- 5種類の徘徊ルートを、個体の性格に合わせて選ぶ
- 家（ドア）を見つけて近づき、**開けて**入る。開かないドアや、つっかえたときは**壊す**
- **ドアが無い建物には窓をぶち破って入る**（ガラスと窓枠の上下1段だけ。それ以外の壁は無傷）
- 家の中のチェストを探し、**食料だけ**を持ち去る。**30%の確率でチェストを壊す**
- プレイヤーを見つけると襲い、**1〜3撃で倒す**（個体差）
- 弓などの**遠距離攻撃**を一定以上受けると**逃げる**。しばらくして縄張りへ戻る

作った物: `bear_ai_addon/dist/熊AI_v0.5.0.mcaddon`（**ファイル名の v が版**）

**配布先**: <https://github.com/my1172-tech/bear-mod/releases/latest>

---

## 1. 入れ方

1. `bear_ai_addon/dist/熊AI_v0.5.0.mcaddon` を**ダブルクリック**する
   （統合版が起動して「インポートが完了しました」と出る。ビヘイビアパックと
   リソースパックの**両方**が入る）
2. ワールドの**設定 → ビヘイビアパック**で「熊AI **v0.5.0** (BP)」を**有効**にする
3. 同じく**リソースパック**で「熊AI **v0.5.0** (RP)」を**有効**にする
   （BPを有効にすればRPは自動で付いてくるが、付かない版もあるので確認する）
4. ワールドに入る。チャットに `[熊AI v0.5.0] 熊が徘徊しています。` と出れば動いている

> **取り込んだだけでは動かない。** ワールドごとに有効化が必要。
> メッセージが出ないときは有効化されていない。

### 版（どれが最新か）

**名前に版が入る。** 同じ名前だと、手元の物もパック一覧に並ぶ物も、
直したあとの物か前の物か分からなくなるため。

| 見るところ | 出るもの |
|---|---|
| 配布ファイル | `熊AI_v0.5.0.mcaddon`（`dist` に置くのは**常に1つだけ**。作り直すと古い物は消える） |
| パック一覧 | `熊AI v0.5.0 (BP)` / `熊AI v0.5.0 (RP)` |
| ゲームの中 | 入ったときのメッセージ・`/function bear_help`・`/function bear_status` の見出し |

古い版を取り込んだままだと一覧に両方並ぶ。**番号の大きいほうを有効にする**
（古いほうは一覧から削除してよい）。

番号は `config.js` の `VERSION` と両方の `manifest.json` の3か所にある。
ずれ・パック名への入れ忘れ・RPだけ上げ忘れは `python tools/check_config.py` が弾く。

- **実験機能（ベータAPI）は不要**。安定版のスクリプトAPI（`@minecraft/server` 2.0.0）だけを使っている
- 対応: 統合版 1.21.80 以降（この端末は 1.26 で確認）
- 教育版でも同じ手順で入る

### 注意（大事）

**熊はドアとチェストを壊す。ワールドが変化する。**
大切なワールドには入れず、**必ずコピーで試す**こと。壊させたくない場合は
`behavior_packs/bear_bp/scripts/config.js` の

```js
export const BREAK_CHANCE = 0.3;        // → 0 にするとチェストを壊さない
export const DOOR_BREAK_CHANCE = 0.35;  // → 0 にするとドアを壊さない
```

を 0 にしてから `python tools/pack.py` で作り直す。

## 2. コマンド

**すべて半角。行頭の `/` を必ず付ける。** チャット欄に打つ。

| コマンド | すること |
|---|---|
| `/function bear_help` | 使えるコマンドの一覧を出す |
| `/function bear_here` | **目の前に1頭出す（見えるかの確認用）** |
| `/function bear_spawn` | 自分の周り（28mほど離れた場所）に熊を3頭出す |
| `/function bear_status` | 今いる熊の数・状態・性格・略奪の成績を出す |
| `/function bear_clear` | 熊を全部消す（目印も片付ける） |
| `/function bear_debug_on` | 熊の頭の上に今の状態を出し、ログにも書く |
| `/function bear_debug_off` | 上を止める |

頭数を指定して出したいときは、`/function bear_spawn` の代わりに

```
/scriptevent bear:spawn 6
```

と打つ（1〜16頭）。`bear:` の前に `/` が必要、コロンは半角。

チートを許可していないワールドでは `/function` が使えない。
設定の「チートの実行」を有効にする。

## 3. 遊び方（おすすめの手順）

1. 町のあるワールド（PLATEAUの都市ワールドなど）に入る
2. `/function bear_spawn` で3頭出す
3. `/function bear_debug_on` にして、頭の上の状態を見ながら追いかける
   - `徘徊` → `家探し` → `侵入` → `物色` → `略奪` と変わっていく
4. 家の中まで付いていくと、チェストの中身が減っていくのが見える
5. 熊の前に出ると襲われる。**1〜3撃で死ぬ**ので、弓で遠くから撃つ
6. 一定以上当てると `逃走` に変わって走って逃げる。追わなければ `復帰` して戻る
7. `/function bear_status` で「どの熊が何回略奪したか」が見られる

自然湧きにも対応している（森・タイガ・山・平地）。放っておいても町へ下りてくる。

## 4. 熊の中身

### 状態（指示書の状態マシンそのまま）

```
待機 → 徘徊 → 家探し → 侵入 → 物色 → 略奪
            ↘ 攻撃 ↘ 逃走 → 復帰 → 徘徊
```

割り込みの強さ（上が強い）: **逃走 > 攻撃 > 略奪 > 侵入 > 家探し > 徘徊**

### 徘徊ルート

| ルート | 名前 | 道のり | 選ばれやすい性格 |
|---|---|---|---|
| A | 水路型 | 森 → 水 → 畑 → 家 | 食料優先が高い |
| B | 道路型 | 森 → 道路 → 家 | 市街地志向が高い |
| C | 境界型 | 高い所 → 市街地の外れ → 縄張り | 市街地を嫌う |
| D | 食料型 | 家 → 家 → 家 | 食料優先・空腹が高い |
| E | 侵入型 | 家 → 道路 → 家 → 外れ | 市街地志向・攻撃性が高い |

ルートは湧いたときに、性格の重み付きで決まる。

### 性格（0.0〜1.0、湧いたときに決まって変わらない）

| 名前 | 効くところ |
|---|---|
| 攻撃性 aggression | 何mからプレイヤーに向かうか / 一撃の重さ / ドアとチェストを壊しやすさ |
| 度胸 bravery | 撃たれても逃げないしきい値 |
| 空腹 hunger | 道中で家探しを始める確率（食べると下がる） |
| 食料優先 foodSeeking | 同上・ルート選び |
| 市街地志向 urbanPreference | 家とチェストを探す半径 / ルート選び |

`/function bear_status` で ■□ の棒として見える。

## 5. 調整のしかた

**数値を変えるときは `behavior_packs/bear_bp/scripts/config.js` だけを触る。**
指示書が「外に出す」と決めた値はすべてここにある。

```
BEAR_HEALTH        熊の体力（既定 40）
BEAR_WIDTH         当たり判定の幅（既定 0.9／必ず 1.0 未満）
BEAR_DAMAGE        プレイヤーを倒すのに要する打撃数（既定 1〜3撃）
CHEST_RANGE        チェストを探す半径（既定 16）
HOUSE_RANGE        家を探す半径（既定 24）
ESCAPE_THRESHOLD   遠距離攻撃で逃げ出す累積ダメージ（既定 6）
ESCAPE_TIME        逃げ続ける時間（既定 200tick = 10秒）
BREAK_CHANCE       チェストを壊す確率（既定 0.3）
WINDOW_ENTRY       窓を割って入るか（既定 true／false で窓を割らない）
WINDOW_STEP_UP     入れる窓の高さ（既定 1／2にすると割れても入れなくなる）
WINDOW_MARGIN      窓枠を上下に広げる段数（既定 1／唯一ガラス以外を壊す場所）
WINDOW_OPEN_MAX    1つの窓で開ける穴の最大の高さ（既定 3段）
```

体力と移動速度だけは、統合版の仕組み上 `entities/bear.json` にも同じ数字が
書いてある（スクリプトから書き換えられない）。**片方だけ直すとずれる**ので、
直したあとは必ず

```
python tools/check_config.py
```

を走らせる。ずれていれば教えてくれる。

道路のブロックは町によって違う（`ROAD_BLOCKS`）。PLATEAUの都市ワールドで
熊が道路を歩かないときは、実際に敷かれているブロックを追加する。

変更したら作り直す:

```
python tools/run_tests.py    # 全部の検査（これが通らないものは配らない）
python tools/pack.py         # dist/熊AI_v版.mcaddon を作り直す（古い物は消える）
```

## 6. 検査

実機で遊ばずに確かめられることは、全部自動で確かめてある。

```
python tools/run_tests.py
```

| 検査 | 見るもの |
|---|---|
| `validate.py` | 定義JSONの整合（モデル・アニメ・音・テクスチャ・importの参照先が実在するか） |
| `check_config.py` | config.js と bear.json の数値のずれ、モード定義の抜け |
| `check_state.py` | 状態名の打ち間違い、優先順位の並び、走査の後始末 |
| `check_uv.py` | モデルの箱とテクスチャの塗り分けのずれ |
| `test_flow.mjs` | 徘徊→侵入→物色→略奪が本当に進むか / 食料だけを取るか |
| `test_runtime.mjs` | 1〜3撃で倒れるか / 遠距離で逃げるか / 10頭でも1tickの読み取りが上限内か / コマンドが答えるか |
| `test_inverse.mjs` | **逆テスト**。確率0なら壊さない / しきい値未満では逃げない / クリエイティブは襲わない など |

`validate.py` は「どこからも呼んでいない export」も弾く。書いたのに繋いでいない
コードは実機で無言の不具合になる（区間を繋ぐ `reachedWaypoint()` を呼び忘れ、
熊が途中の目印で止まっていた）。

机上試験は**本物のスクリプトをそのまま**偽のマイクラ（`tools/test/mcstub.mjs`）で
動かしている。写しではないので、コードを直せば試験も一緒に追随する。

### 実機でしか確かめられないこと

机上試験には経路探索も当たり判定も無い。**次の9項目は実機で見る必要がある。**

- [ ] 熊が湧く（`/function bear_spawn` と自然湧きの両方）
- [ ] 歩き方が自然（脚が動く・段差を越える・地形を無視して滑らない）
- [ ] ドアを開けて家に入る
- [ ] 開かないドアを壊して入る
- [ ] チェストの中身（食料だけ）が減る
- [ ] チェストが確率で壊れ、食料以外は床にこぼれる
- [ ] プレイヤーが1〜3撃で倒れる
- [ ] 弓で撃つと逃げ、しばらくして戻る
- [ ] 熊が10頭ほどいても重くならない

### うまくいかないときの切り分け

**返事の文言と `bear_status` で原因が分かるようにしてある。** 順に見る。

| 見るもの | 出たもの | 意味 |
|---|---|---|
| `/function bear_spawn` | `熊を3頭出しました 1088,1216 / …` | 出ている。座標も出るのでそこへ行く |
| 〃 | `熊を出せませんでした: <理由>` | ビヘイビアパックの熊の定義が読めていない |
| 〃 | `湧かせる場所が見つかりませんでした` | 立てる場所が無い（屋上・洞窟）。足元にも出せなかったとき |
| `/function bear_status` | `目印(誘導体)を出せていません: <理由>` | **熊はいるが行き先を持てない**。うろつくだけになる |
| 〃 | 各行の末尾 `→なし` | まだ行き先が無い（走査待ち）。続けて見て変わらなければ上の行を疑う |
| `/function bear_debug_on` | 頭の上に名札が出る | 熊はそこに居る。**名札は模型が無くても出る**ので、名札だけ見えて体が見えないならリソースパックが入っていない |
| 〃 | 名札も出ない | その場所に熊はいない |
| `/function bear_status` | `足が止まっている熊 n 頭` | n が頭数と同じなら全体が動いていない。上の目印の行を疑う |
| 〃 | `n 頭がブロックに食い込んで動けません` / 行末の `[埋]` | 掘り出す先が無い場所（地中・完全に塞がれた室内）。`/function bear_clear` で消して出し直す |
| 〃 | 行末の `[止3]` | その熊が3周期動いていない。数字が増え続けなければ正常（信号待ちのようなもの） |

`徘徊` のまま動かない場合は「目印を見つけられていない」ので、
`config.js` の `LEG_DISTANCE` を小さくする（既定 24〜56m）。

### 「そもそも熊が見当たらない」とき

**まず `/function bear_here` を打つ。** 目の前に1頭出て、見分け方まで答える。
`bear_spawn` は 28m 離れた場所に出すので、見えているかの確認には使えない。

| 見えたもの | 意味 |
|---|---|
| 体も名札も見える | 正常 |
| **名札だけ見える** | リソースパック（見た目）が効いていない |
| どちらも見えない | その場所に熊が出せていない（返事の文言を読む） |

見た目が丸ごと出ないときは、コンテンツログの `[Animation][error]` /
`[Render][error]` を見る。**定義が1か所でも弾かれると、その実体は
エラーだけ出して何も描かれない。** v0.2.0 では
`description | animation_controllers | child not valid here.` が出ていた。

### 「詰まって動けない」が続くとき

**当たり判定の幅が原因のことが多い。** 統合版はブロックに食い込んだ実体を
押し出してくれないので、幅が 1.0 以上あると幅1のドアや路地を通れず、
入口に食い込んだまま一歩も動けなくなる（地面に埋まったように見える）。
`config.js` の `BEAR_WIDTH`（既定 0.9）は**必ず 1.0 未満**にする。
`entities/bear.json` の `collision_box.width` にも同じ数字が要るので、
直したら `python tools/check_config.py` で確かめる（ずれと 1.0 以上の両方を弾く）。

熊が本当にブロックの中にいるときは、近くの立てる場所へ自動で掘り出す
（`STUCK_RECOVER`）。掘り出した回数は `/function bear_status` に出る。
**動いていないだけの熊は動かさない**（瞬間移動して徘徊に見えなくなるため）。

教育版で細かい失敗を全部見たいときは、設定 → 一般 → **コンテンツログ**（ファイル・画面）
を入れる。`[bear] …` の行が
`%LOCALAPPDATA%\Packages\Microsoft.MinecraftEducationEdition_8wekyb3d8bbwe\LocalState\logs\`
に残る。

## 8. 費用と安全について

- **費用はかからない。** 通信も外部サービスも使っていない
- スクリプトはマイクラのサンドボックス内だけで動く。ファイル書き出しも通信もしない
- モデルとテクスチャは自作生成（`tools/make_textures.py`）。バニラの素材ファイルは
  コピーしていないので、配布上の権利の問題もない
- 音だけは統合版に元からある音ID（`mob.polarbear.*`）を鳴らしている（ファイルは同梱しない）
- 唯一の副作用は**ワールドのドアとチェストが壊れること**（仕様）。コピーで遊ぶこと
